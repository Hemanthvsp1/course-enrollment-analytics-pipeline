# Power BI Dashboard Specification

## Data Sources

Preferred source: PostgreSQL views in the `analytics` schema.

Local fallback: CSV exports generated by `scripts/export_powerbi_views.py` under `data/processed/powerbi/`.

## Model

Use the analytics views as fact-style reporting tables:

- `v_enrollment_trends`
- `v_capacity_utilization`
- `v_pass_rates`
- `v_department_performance`

For a compact portfolio dashboard, importing these views directly is sufficient. For a larger semantic model, split `term`, `department`, and `course` into shared dimensions.

## Dashboard Pages

### 1. Enrollment Overview

Recommended visuals:

- Line chart: `enrolled_students` by `term_name`
- Stacked column chart: `enrolled_students` by `department_code` and `term_name`
- Card: total active enrollments
- Card: total withdrawals

### 2. Capacity & Demand

Recommended visuals:

- Bar chart: `capacity_utilization_pct` by `course_code`
- Table: course title, capacity, enrolled students, utilization
- Conditional formatting: highlight utilization above 90 percent or below 50 percent

### 3. Pass Rate Analysis

Recommended visuals:

- Bar chart: `pass_rate_pct` by `course_code`
- Scatter plot: `average_grade` versus `graded_enrollments`
- Slicer: `department_code`
- Slicer: `term_name`

### 4. Department Performance

Recommended visuals:

- Matrix: department by term with active enrollments, pass rate, average grade, and utilization
- Clustered bar chart: `active_enrollments` by department
- KPI cards: highest enrollment department, average pass rate, average capacity utilization

## Suggested DAX Measures

```DAX
Total Enrollments = SUM(v_department_performance[active_enrollments])

Average Pass Rate = AVERAGE(v_department_performance[pass_rate_pct])

Average Capacity Utilization = AVERAGE(v_department_performance[capacity_utilization_pct])

Withdrawal Count = SUM(v_department_performance[withdrawals])
```

## Interview Talking Points

- The model separates source staging tables from analytics views, which keeps ingestion and reporting concerns clean.
- Python validation catches duplicate primary keys, invalid statuses, bad grades, and missing foreign keys before database loading.
- SQL views keep reporting logic transparent and reusable across Power BI and ad hoc analysis.
